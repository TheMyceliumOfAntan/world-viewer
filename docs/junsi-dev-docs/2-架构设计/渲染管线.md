# 渲染管线

## 1. 流程总览

```
render_tile(cache, region_dir, zoom, tile_x, tile_row, ymax)
  │
  ├─ 1. 计算覆盖范围
  │     chunks_per_tile = 16 >> zoom      (z0=16, z4=1)
  │     blocks = chunks_per_tile * 16
  │
  ├─ 2. 并行加载区块（含 1 区块边距）
  │     Surface::fill()
  │       ├─ 收集未缓存的区块坐标（-1 ..= chunks_per_tile）
  │       ├─ load_chunks_parallel() 多线程读取
  │       └─ 按区块取每个 (x,z) 列的最高非空气方块
  │
  ├─ 3. 浮雕着色  Surface::shade()
  │
  ├─ 4. 降采样  Surface::to_rgba()
  │
  └─ 5. PNG 编码  encode_png()
```

## 2. Surface：瓦片级缓冲

```rust
pub struct Surface {
    blocks: usize,        // 瓦片边长（方块数）
    side: usize,          // blocks + 2（含 1 格边距）
    color: Vec<[u8; 3]>,  // 每格颜色
    height: Vec<i32>,     // 每格高度；EMPTY = i32::MIN 表示无方块
}
```

**为什么带边距**：浮雕着色需要比较相邻方块的高度差。若只渲染瓦片自身范围，边缘像素无法与瓦片外的方块比较，会产生可见接缝。因此：
- **1 格边距**：让边缘像素也能算中心差分
- **1 区块边距**：区块内部 16 格都需要正确的邻居，故向外多读一圈区块

边距区域只用于计算，不参与最终输出（`to_rgba` 只输出内部 `blocks × blocks`）。

## 3. 浮雕着色（hillshade）

参照 VoxelMap 的 `applyHeight()` 思路，但用标准制图学公式。

### 3.1 中心差分

对每个格子取水平/垂直方向的中心差分：

```
dx = (h[x+1, z] - h[x-1, z]) * 0.5
dz = (h[x, z+1] - h[x, z-1]) * 0.5
```

`EMPTY`（无方块）的邻居按当前格子高度处理，避免边界出现异常暗边。

### 3.2 光照合成

```
坡度项 slope = (dx + dz) * 0.18
高度项 elev  = sign(h-64) * log10(|h-64|/8 + 1) / 5
最终  shade = clamp(1 + slope + elev, 0.45, 1.55)
```

**光照方向**：光来自西北。因此**朝东南抬升**的地形（坡面朝西北）被照亮，反之变暗。这是标准制图学约定。

> 注意：这里容易搞反。物理推导：法线 `N = (-∂h/∂x, 1, -∂h/∂z)`，光源 `L` 来自西北即 `(-1, 1, -1)` 方向，则 `N·L ∝ ∂h/∂x + ∂h/∂z`。所以 `dx + dz > 0`（朝东南抬升）时更亮。

### 3.3 高度项的作用

高度项提供大尺度起伏感，以海平面（y=64）为基准，用对数压缩避免高山过曝。系数 `/5` 是经验值，让高度项影响弱于坡度项。

## 4. 方块配色

`Palette::color_ref(BlockRef)` 的解析顺序：

| 顺序 | 来源 | 说明 |
|------|------|------|
| 1 | JourneyMap 调色板 | `uid + meta → hex`，精确匹配优先 |
| 2 | 内置原版表 | `legacy_ids.rs`，用于无 JM 调色板的实例 |
| 3 | 兜底 | 灰色 `#505050` |

返回 `(rgb, source, block_name)`，其中 `source` 取值 `exact` / `meta0` / `first` / `vanilla` / `unknown` / `air`，便于诊断。

> **旧版方块名**：1.13 扁平化重命名了大部分方块（`grass` → `grass_block` 等），内置表按现代名建键。1.0–1.12.2 的存档走 `LEGACY_ALIASES` 别名表解析为现代名，否则全部落灰。详见 `7-调用规范/存档格式支持.md` 3.2。

### 4.1 生物群系染色

JourneyMap 调色板对草地/树叶存的是**未染色的灰度纹理色**，直接渲染会灰蒙蒙。因此对属于原版 `grass` / `foliage` 染色类别的方块，乘以生物群系绿色：

```rust
fn apply_foliage_tint(c: [u8; 3]) -> [u8; 3] {
    const BIOME: [f32; 3] = [0x79, 0xc0, 0x5a];  // 平原草色
    [c[0]/255*BIOME[0], c[1]/255*BIOME[1], c[2]/255*BIOME[2]]
}
```

`is_foliage()` 的分类依据见 `1-决策记录/ADR-001` 与 `7-调用规范/存档格式支持.md`。

> 当前使用固定平原绿。按实际生物群系取色需要读 colormap 温度/湿度，属待办。

## 5. 区块缓存

```rust
pub struct TileCache {
    chunks: HashMap<(i32, i32), Option<ChunkData>>,
    palette: Palette,
    capacity: usize,   // open_world 时设为 4096
}
```

- `None` 表示"该区块不存在"，也缓存，避免重复读盘
- 淘汰策略：容量满时移除最早插入的 1/4（`HashMap` 迭代顺序，非严格 LRU）
- `invalidate()` 清空全部，用于手动刷新

单瓦片需 324 个区块（含边距），一屏约 16 瓦片。容量 4096 约可覆盖两屏多，平移几屏后会触发淘汰。

## 6. 并行加载

```rust
fn load_chunks_parallel(region_dir, coords) -> Vec<((i32,i32), Option<ChunkData>)>
```

- 线程数 = `available_parallelism()`，上限 8
- 坐标数 < 4 或线程数 ≤ 1 时退化为串行
- 用 `std::thread::scope` 分片，避免引入 rayon 依赖
- 结果按原顺序返回，保证渲染确定性

## 7. 性能优化要点

### 7.1 定向 NBT 解析（4.4x）

区块 NBT 中 `Entities` / `TileEntities` 占大部分体积（GTNH 单区块可达 747 个 tile entity），但渲染完全用不到。`Reader::skip()` 跳过这些子树而不构建 `Tag`：

```
通用解析（整棵树）  1.023 ms/chunk
定向解析（只取 Sections） 0.231 ms/chunk
```

正确性由 `tests/fast_parser.rs` 保证：对 49 个真实区块逐字节比对两种解析器的输出。

### 7.2 异步协议响应

协议处理器内**必须** `std::thread::spawn` 后再渲染。同步渲染会阻塞 Tauri 事件循环，导致拖拽/缩放时窗口卡顿（实测 700ms 级 long task）。

### 7.3 前端并发限流

`CachedTileLayer` 限制同时 6 个请求，其余排队。避免一次性发出上百请求拖垮后端。
