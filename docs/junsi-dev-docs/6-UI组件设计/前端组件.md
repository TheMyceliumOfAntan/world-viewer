# 前端组件

## 1. 结构总览

```
src/
  main.tsx        React 入口
  App.tsx         主组件：状态、地图、维度列表、标记、状态栏
  tileLayer.ts    CachedTileLayer：自定义瓦片层
  styles.css      全局样式（深色主题）
```

组件数量少是刻意的：功能集中在 `App.tsx`，唯一需要独立抽象的是瓦片加载逻辑（因为要重写 Leaflet 的 `GridLayer`）。

### 2.5 坐标系

使用 `L.CRS.Simple`，映射关系：

```
lat = -worldZ
lng =  worldX
```

zoom 0 时 1 瓦片 = 256 世界单位 = 256 方块。

### 2.6 状态栏的 Y 坐标与方块信息

底部状态栏显示 `X= Y= Z=` 与当前列的最高方块（名称 + 原始 id）。Y 不在 `CRS.Simple` 平面内，必须由后端 `probe_block` 查询（见 `3-API规范` §1.5）。

实现要点：

- `mousemove` 注册在 `ensureMap()` 里**只执行一次**，所以处理器通过 `latestRef` 读取当前的 `dim`/`ymax`/是否已加载，避免闭包读到旧值。
- `scheduleProbe(x, z)` 以 150ms 节流：只记录最新坐标，定时器到期才真正发一次 `probe_block`。实测 331 次鼠标移动 → 12 次调用，最小间隔 156ms。
- `runProbe` 用递增的 `probeSeqRef` 序号，仅当回包序号仍是最新时才 `setBlock`，防止慢回包覆盖新结果。
- 未加载存档时不查询，直接清空显示。
- 卸载时清理未触发的定时器。

**状态栏必须保持单行**：`.statusbar span` 设 `white-space: nowrap; overflow: hidden; text-overflow: ellipsis; min-width: 0`。模组方块名可能很长，若允许换行会把状态栏撑成两行并从地图偷走高度（实测地图高度 780→764px）。修复后 400 字符名称下地图高度仍为 780px。

### 2.7 深链

支持 `?save=<路径>` 查询参数，页面加载后自动打开该存档：

```
http://localhost:1420/?save=C%3A%5C.minecraft%5C...%5C新的世界
```

用途：自动化测试可在刷新页面后恢复世界，也便于手动分享。

## 3. `tileLayer.ts` — `CachedTileLayer`

继承 `L.GridLayer`，替代 `L.tileLayer` 以解决三个问题：

| 问题 | 原生 `L.tileLayer` 的行为 | `CachedTileLayer` 的解法 |
|------|--------------------------|------------------------|
| 平移/缩放时出现空白洞 | 瓦片到达前显示空白 | 缓存 + 父瓦片缩放占位 |
| 请求风暴 | 一次性发出所有可见瓦片请求 | 并发上限 6 + 队列 |
| 重复请求丢失回调 | — | `waiting` 订阅列表，全部通知 |

### 3.1 内部字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `cache` | `Map<string, ImageBitmap>` | 已解码瓦片 |
| `empty` | `Set<string>` | 服务端标记为"无数据"的瓦片 |
| `waiting` | `Map<string, Array<cb>>` | 同一瓦片的待通知回调 |
| `queue` | `Array<() => void>` | 待执行请求 |
| `active` | `number` | 进行中的请求数 |
| `failures` | `Set<string>` | 失败的瓦片，避免无限重试 |
| `urlTemplate` | `string` | 当前 URL 模板 |

### 3.2 加载流程

```
load(key, url, onReady)
  ├─ 命中 cache        → 立即回调
  ├─ 已在 waiting      → 追加回调（关键：不丢弃）
  ├─ 已知失败          → 回调 null
  └─ 否则
       ├─ waiting.set(key, [onReady])
       └─ 入队 → fetch(url, {mode:"cors"})
            ├─ 读 X-Tile-Empty 头
            ├─ createImageBitmap(blob)
            ├─ cache.set(key, bitmap)
            └─ 通知所有 waiting 回调
```

### 3.3 父瓦片占位

`createTile()` 中，若 `z > 0` 且父瓦片（`z-1`，坐标减半）已缓存，则先把它放大 2 倍并裁剪到当前象限绘制到 canvas，同时 `opacity: 1`。清晰瓦片到达后覆盖重绘。

效果：缩放时地图保持连续（模糊），而不是出现空洞。

### 3.4 空数据标记

若响应头 `X-Tile-Empty: 1`，绘制 16px 棋盘格（`rgba(255,255,255,0.035)` / `0.07`），表示"该区域从未生成"。

与"加载中"的区别：加载中是透明（或父瓦片模糊图），无数据是可见棋盘格。

### 3.5 模板切换必须清空队列（ymax / 世界切换）

`setUrlTemplate()` 在模板变化时除了清 `failures`/`empty`，还必须清空 `queue` 与 `waiting`：

```ts
setUrlTemplate(template: string) {
  if (this.urlTemplate === template) return;
  this.urlTemplate = template;
  this.failures.clear();
  this.empty.clear();
  this.queue.length = 0;   // 旧模板的 URL 已失效
  this.waiting.clear();    // 否则回调成为孤儿，同 key 再访问会永久卡住
  this.redraw();
}
```

**为什么**：高度滑块每次 `onChange` 都会重建 URL 模板并 `redraw()`。若保留队列，快速拖动会把旧 ymax 的请求堆到队首，新 ymax 的瓦片排到队尾——实测积压 3133 个请求，地图持续全黑约 35 秒直到积压排空。清空后同一场景 2.5 秒内出图。

`waiting` 必须与 `queue` 同时清：入队前已把回调登记进 `waiting`，只丢队列会让回调永远等不到通知；若用户拖回同一 ymax，该 key 命中 `waiting` 分支被追加而非重新请求，瓦片将永久空白。

### 3.6 小数缩放必须取整（`_clampZoom` 覆写）

地图启用 `zoomSnap: 0.25`（`App.tsx`），滚轮/触控板缩放会停在 `2.5`、`3.5` 这类小数 `mapZoom`。此时点击高度滑块（大跨度切层）会触发 `setUrlTemplate()` → `redraw()`，而 Leaflet 的 `redraw()` 与 `_update()` 直接把 `map.getZoom()` 当瓦片 zoom 用（**不取整**），`_tileZoom` 因此变成 `0.5`，瓦片 key 变成 `-3:-2:0.5`，URL 变成 `/0.5/-3/-2.png`。

后端 `tile_from_uri` 用 `parse::<i32>()` 解析 zoom，小数解析失败 → 协议返回 404 → 前端 `failures` 记录后不再重试 → **地图全黑**。缩放一次会走 `_setView`（其内部 `Math.round`）把 zoom 修正回整数，所以现象是「全黑后随便缩放一次就正常」。

修复：覆写三处路径共用的 `_clampZoom`，在唯一入口取整：

```ts
protected _clampZoom(zoom: number): number {
  const base = L.GridLayer.prototype as unknown as { _clampZoom(zoom: number): number };
  return base._clampZoom.call(this, Math.round(zoom));
}
```

**为什么改这里而不是改 `zoomSnap`**：`_setView`、`redraw`、`_update` 三条路径都经过 `_clampZoom`，一处收口即可，且保留 0.25 平滑缩放粒度。实测：`mapZoom=0.5` + 点击切层，修复前 `dark=100%`、`zs=["0.5"]`（0.5 的 URL `fetch` 直接 `Failed to fetch`）；修复后 `dark=23.1%`、`zs=["1"]`，全部瓦片 200。真实交互（滚轮缩放 + 滑块点击）12/12 通过，其中 6 次命中小数缩放。

### 3.7 诊断接口

`stats()` 返回 `{cached, waiting, queued, active, failed, empty}`，通过 `window.__tileLayer` 暴露，供自动化测试断言。
