# 存档格式支持

本文档列出工具支持的存档与配套数据格式，以及各格式的解析要点。新增格式支持前请先阅读本文档，避免重复实现或破坏既有路径。

## 1. 支持的 Minecraft 版本

| MC 版本 | 区块格式 | 方块标识 | 方块名来源 | 状态 |
|---------|---------|---------|-----------|------|
| 1.7.10 | `Blocks16` + `Data16`（16 位 id，NotEnoughIDs 扩展） | 数字 id + meta | `level.dat` → `FML.ItemData` | 完整支持 |
| 1.12.2 | `Blocks` + `Add`（4 位高位扩展）+ `Data` 半字节 | 数字 id + meta | `FML.Registries.minecraft:blocks.ids`（仅模组方块）+ 内置原版表 | 完整支持 |
| 1.13+ | `sections[].block_states`（调色板 + 位压缩） | 命名空间名 | 区块调色板自带 | 完整支持 |

### 1.1 格式自动探测

`render::load_chunk()` 先尝试旧格式解析，结果为空则用新格式：

```rust
let sections = match region::parse_sections_fast(&nbt_bytes) {
    Ok(s) if !s.is_empty() => s,
    _ => region::parse_sections_modern(&nbt_bytes)?,
};
```

**结构差异**：
- 旧格式（≤1.12）：sections 嵌套在 `Level` 下，`Y` 为 TAG_Byte
- 新格式（1.13+）：sections 位于根节点，`Y` 可为负，调色板条目是含 `Name`/`Properties` 的 compound

### 1.2 1.13+ 位压缩规则

`bits` 由调色板长度决定（依据 Minecraft Wiki 扁平化格式）：

| 调色板长度 | bits |
|-----------|------|
| 0 或 1 | 0（无 data，全部为 palette[0]） |
| 2..16 | 4 |
| 17..32 | 5 |
| 33..64 | 6 |
| 65..128 | 7 |
| 129..256 | 8 |
| >256 | 9 |

方块顺序为 YZX（`(y*16 + z)*16 + x`），与旧格式的 XZY 不同。

## 2. 方块名映射

`Palette::load()` 按以下顺序填充，**先到者优先**，后到者只填补空缺：

| 顺序 | 来源 | 覆盖范围 |
|------|------|---------|
| 1 | `level.dat` → `FML.ItemData`（前缀 `\x01`） | 1.7.10：全部方块（GTNH 实测 4038 个） |
| 2 | `level.dat` → `FML.Registries.minecraft:blocks.ids` | 1.12.2：仅模组注册的方块（实测 277 个） |
| 3 | `legacy_ids::VANILLA_1_12_2` 或 `VANILLA_1_7_10` | 原版方块兜底 |

内置表的选择依据：若已映射的 id 中存在 176..255 区间的条目，判定为 1.12.2 表，否则用 1.7.10 表。

> 1.12.2 的 `FML` 下**没有** `ItemData`（1.13 移除），只有 `Registries`，且后者不含原版方块。因此内置原版表是必需的，否则整个存档渲染为灰色。

### 2.5 `level.dat` 解析要点

`level.dat` 是 gzip 压缩的 NBT，`Data` compound 下含本工具所需的全部元信息。三次读取各自独立（`world::read_level_name` / `palette::load_player` / `world::read_world_seed`），当前未做单次解析共享。

| 字段 | 路径 | 用途 |
|------|------|------|
| 存档名 | `Data.LevelName`（TAG_String） | `WorldInfo.save_name` / `level_name` |
| 玩家位置 | `Data.Player.Pos` / `Dimension` / `name` | `WorldInfo.player` |
| 世界种子 | `Data.WorldGenSettings.seed` | `WorldInfo.world_seed` |
| 世界种子（旧版） | `Data.RandomSeed` | 上者缺失时的回退 |
| 方块表（1.7.10） | `Data.FML.ItemData` | 方块 id → 名称映射 |
| 方块表（1.12.2） | `Data.FML.Registries.minecraft:blocks.ids` | 模组方块 id → 名称映射 |

#### 世界种子的回退链与类型

```rust
data.get("WorldGenSettings")
    .and_then(|w| w.get("seed"))
    .and_then(|s| s.as_i64())
    .or_else(|| data.get("RandomSeed").and_then(|s| s.as_i64()))
    .map(|v| v.to_string())
```

- **1.16+** 用 `WorldGenSettings.seed`；**1.16 以前**用 `RandomSeed`。
- 两者都缺失（或值非整数类型）时返回 `None`，`WorldInfo.world_seed` 序列化为空串。
- **必须以字符串跨 IPC 传递**：种子是 `i64`，范围可达 ±2^63，超过 JS `Number.MAX_SAFE_INTEGER`（2^53-1）。以数字序列化会让前端静默丢失低位精度。Rust 侧 `to_string()`，前端按字符串原样展示。
- NBT 读取依赖 `nbt::Tag::as_i64()`，它接受 Byte/Short/Int/Long 四种整型（不同版本可能用不同宽度存储）。

## 3. 方块配色

### 3.1 解析顺序

| 顺序 | 来源 | 说明 |
|------|------|------|
| 1 | `journeymap/colorpalette.json` | `uid + meta → hex`，精确匹配 → meta 0 → 任意 |
| 2 | `palette::vanilla_color()` | 内置约 130 项原版表 + 名称后缀规则 |
| 3 | 兜底灰色 | `#505050` |

调色板文件是 JS 包装（`var colorpalette={...};`），需剥离后再 JSON 解析。

### 3.2 内置原版表的后缀规则

未精确匹配时按名称后缀推断，避免模组方块全灰：

| 后缀/包含 | 颜色 |
|----------|------|
| `_leaves` | 叶绿 |
| `_log` / `_wood` | 木色 |
| `_planks` | 木板色 |
| `_ore` | 石灰色 |
| `water` | 水蓝 |
| `lava` | 岩浆橙 |
| `glass` | 浅青 |
| `_concrete` | 中灰 |
| `_terracotta` | 陶土色 |
| `slab` / `stairs` | 石灰色 |

### 3.3 生物群系染色（关键）

JourneyMap 调色板对草地/树叶存的是**未染色的灰度纹理色**（如 `minecraft:grass` → `#939393`），直接渲染会灰蒙蒙。因此对属于原版染色类别的方块乘以生物群系绿色。

**染色类别**（依据 [wiki.bedrock.dev/blocks/block-tinting](https://wiki.bedrock.dev/blocks/block-tinting)）：

| 类别 | 方块 |
|------|------|
| `grass` | `grass_block`(顶面)、`short_grass`/`tall_grass`/`tallgrass`、`fern`/`large_fern`、`reeds`/`sugar_cane`、`double_plant`、`grass_path`、`wildflowers` |
| `foliage` | 各类 `*_leaves`、`leaves`/`leaves2`、`vine`/`vines` |

**模组扩展**（实测出现在 GTNH 地表）：`BiomesOPlenty:foliage`、`Thaumcraft:blockMagicalLeaves`、`IC2:blockRubLeaves`、名称含 `foliage`/`tallgrass` 或 `_grass` 后缀者。

**必须排除**：花朵、作物、蘑菇、仙人掌、睡莲 —— 它们有自己的颜色，染色会变绿。

> **禁止**用显示名做分类。`color_ref()` 返回的第三个值必须是规范方块 id 名（`minecraft:grass`），显示名（`草方块`）只用于 tooltip。混用会导致染色静默失效。详见 `1-决策记录/ADR-001`。

### 3.4 实测覆盖率

同一瓦片（GTNH 平原，`dim0 z0 x-2 y-2`）：

| 指标 | 修复后 |
|------|--------|
| 彩色占比 | 98.5% |
| 灰阶占比 | 1.5% |
| 绿色植被 | 39.3% |
| 色相数 | 283 |

## 4. 路径点格式

`palette::load_waypoints()` 聚合三种来源，`Waypoint.source` 标注来源。

### 4.1 JourneyMap

```
journeymap/data/sp/<存档名>/waypoints/*.json
```

单文件单点，`dimensions` 数组可含多个维度（展开为多条）。字段：`name` / `x` / `y` / `z` / `r` / `g` / `b` / `enable` / `type`。

### 4.2 Xaero

```
xaero/minimap/<世界>/dim%<id>/*.txt
xaero/world-map/<世界>/<DIM 目录>/*.txt
```

行格式：

```
waypoint:name:initials:x:y:z:color:disabled:type:set:rotate_on_tp:tp_yaw:visibility_type:destination
```

| 要点 | 说明 |
|------|------|
| 维度来源 | 目录名。`minimap` 树用 `dim%0` / `dim%-1`；`world-map` 树用 `DIM-1` / `DIM1` / `null`（null = 主世界） |
| 颜色 | **调色板索引**（非 RGB），映射为 16 色表 |
| i18n | `gui.xaero_deathpoint` → `死亡点`；`gui.xaero_manual` → `标记` |
| 去重 | `minimap` 与 `world-map` 两棵树都扫描，按 `(name, x, y, z, dim)` 去重 |

### 4.3 VoxelMap

```
voxelmap/<存档名>.points
```

行格式（逗号分隔的 `key:value`）：

```
name:..,x:..,z:..,y:..,enabled:..,red:..,green:..,blue:..,suffix:,world:,dimensions:<ids>#
```

| 要点 | 说明 |
|------|------|
| 维度 | 行内 `dimensions` 字段，多个 id 用 `#` 分隔 |
| 颜色 | 0..1 浮点三元组，需转 hex |
| 文件名匹配 | 优先匹配存档名；不匹配则跳过 |

### 4.4 共同行为

- `enabled` / `disabled` 为 false 的路径点一律跳过
- 维度 id 直接使用存档内的数值，与 `DimensionInfo.id` 对应

## 5. 维度命名

`palette::dimension_name()` 依次尝试：

1. **硬编码已知维度**：`-1` 下界、`0` 主世界、`1` 末地、`7` 暮色森林、`2` 幽灵世界、`55`/`56`/`70` Witchery 三界、`100` 深暗世界、`112` 千年村庄
2. **Galacticraft**：`config/Galacticraft/planets.conf` 与 `core.conf`（月球 28、火星 29、小行星带 30）
3. **GalaxySpace**：`config/GalaxySpace/dimensions.conf`，解析 `I:dimensionID<名称>=<id>`
4. 未匹配则显示 `DIM<id>`

只有含 `region` 目录且有 `.mca` 文件的维度才会出现在列表中。

## 6. 实例根探测

`world::detect_instance_root()` 从存档目录向上最多 5 层，找到含 `journeymap/` 或 `mods/` 的目录即认为是实例根。该路径用于定位调色板、路径点与模组配置。

若探测失败，回退到存档的父目录。
