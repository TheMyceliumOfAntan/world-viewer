# ADR-001：渲染管线中方块标识与显示名必须分离

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-09-14 |
| 决策者 | AI Agent |

## 背景

为支持多版本存档（1.7.10 / 1.12.2 / 1.13+），引入 BlockRef 枚举统一表达方块，并把调色板查询改为 color_ref()。改动中 color_ref 返回了 JourneyMap 调色板的 name 字段（人类可读显示名，如"草方块"），而渲染器用这个返回值做方块分类判断（is_foliage）以决定是否施加生物群系染色。结果 is_foliage("草方块") 恒为 false，草地/树叶染色完全失效。实测同一瓦片绿色植被占比从 79.9% 彩色 / 17.8% 绿色跌到 64.5% / 2.8%，平原看起来灰蒙蒙。该回归在测试中未被发现，因为当时没有断言"color_ref 返回的名字必须可被分类器使用"。

## 决策

color_ref() 的第三个返回值固定为规范方块 id 名（如 minecraft:grass），永不返回显示名。新增 display_name() 单独提供人类可读名（优先 JM 显示名，回退方块 id），仅供 tooltip/弹窗使用。渲染器只依赖 color_ref 的 id 名做分类。新增测试 color_ref_name_is_usable_for_classification 断言该契约，还原 bug 后测试必须 FAILED。

## 备选方案

### 方案 让 is_foliage 同时接受显示名
- 优点：改动小
- 缺点：需要维护中文/多语言显示名映射，语言变化即失效，且分类逻辑被 I/O 数据污染
- 为何不选：不可靠且不可扩展

### 方案 渲染器改用 name_of(id) 单独取 id 名
- 优点：不动 color_ref 签名
- 缺点：调用方需要两次查询，且 Named 分支（1.13+）没有数字 id，仍需 BlockRef 内部分支
- 为何不选：重复查询且对 1.13+ 无效

### 方案 color_ref 返回 id 名 + 新增 display_name
- 优点：职责清晰，id 名与显示名分离，分类契约可测试
- 缺点：改动两个函数签名
- 为何不选：采纳

## 影响
- src-tauri/src/palette.rs：color_ref 返回 id 名，新增 display_name()
- src-tauri/src/render.rs：is_foliage 精确对齐原版 grass/foliage 染色类别
- src-tauri/tests/tint_regression.rs：新增契约测试
- src-tauri/tests/colors.rs：更新分类断言
