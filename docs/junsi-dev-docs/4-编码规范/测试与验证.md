## 2. 测试设计原则

### 2.1 对真实数据断言，而非构造数据

绝大多数测试直接读本机真实存档。找不到文件时 `eprintln!("SKIP: ...")` 后返回，不失败——这样 CI 环境缺存档也能跑。

**但断言必须是精确值**，例如：

```rust
assert_eq!(home.x, 84);          // Xaero home 的真实坐标
assert_eq!(home.dimension, 0);   // dim%0 必须映射为 0
assert_eq!(p.color, "#663d92");  // VoxelMap 浮点色转 hex
```

而不是 `assert!(wps.len() > 0)` 这类弱断言。

### 2.2 像素级断言，而非"能渲染"

曾发生过"测试全绿但功能坏了"的教训：测试只断言"渲染出了颜色"，没断言"颜色正确"，导致草地染色失效未被发现。

现在对渲染结果断言具体统计量：

```rust
// colors.rs
assert!(coloured_pct > 25.0, "1.12.2 瓦片仍以灰阶为主: {:.1}%", coloured_pct);

// tile_pipeline.rs
assert!(colors.len() > 400, "配色变化不足: 仅 {} 种颜色", colors.len());
let (min, max) = (lums.iter().min(), lums.iter().max());
assert!(max - min > 60, "亮度范围过平: {}..{}", min, max);
```

### 2.3 契约测试

当两个模块通过隐式约定耦合时，写测试把约定固定下来。例如 `tint_regression.rs`：

```rust
// 渲染器依赖 color_ref 返回的名字做分类。若返回显示名（"草方块"），
// 分类恒为 false，染色静默失效。
assert!(
    testing::is_foliage(&name),
    "color_ref 返回 {:?}，is_foliage 无法分类。\
     渲染器依赖这个名字决定是否染色，返回显示名会导致草地失色。",
    name
);
```

这类测试的价值在于**失败信息直接指出后果**，而不只是"断言失败"。

### 2.4 回归验证（改完必须做）

修复 bug 后，**必须临时还原 bug 确认测试会失败**，否则无法证明测试有效。

标准流程：

```bash
# 1. 备份
Copy-Item src/palette.rs $TEMP/pal.bak

# 2. 还原 bug
(替换代码)

# 3. 确认失败
cargo test --test tint_regression
# → FAILED: color_ref returned "草方块", which is_foliage cannot classify

# 4. 恢复
Copy-Item $TEMP/pal.bak src/palette.rs -Force
(Get-Item src/palette.rs).LastWriteTime = Get-Date   # 关键：cargo 依赖 mtime
```

> **坑**：`Copy-Item` 会保留备份文件的旧时间戳，导致 cargo 认为无需重编译而跑旧二进制。恢复后必须 touch 修改时间。

## 4. 端到端验证（CDP）

Tauri 的 WebView2 可开远程调试，用 Node 内置 WebSocket 直连 CDP 驱动真实 UI。

### 4.1 启动带调试端口的应用

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = '--remote-debugging-port=9223'
Start-Process 'src-tauri\target\debug\world-viewer.exe'
```

注意：9222 常被其他 WebView2 应用（如网易 GameViewer）占用，用 9223。

### 4.2 辅助脚本（存于临时目录）

| 脚本 | 用途 |
|------|------|
| `cdp.js` | 通用：`eval` / `shot` / `click` / `console` / `requests` |
| `cdp-load.js` | 调用 `open_world` 并打印 `WorldInfo` |
| `cdp-ui-all.js` | 逐个加载存档，捕获控制台错误 |
| `cdp-ui-shots.js` | 逐个加载并截图 |
| `cdp-verify.js` | 瓦片分类：真实/空/卡住 |
| `cdp-perf.js` | 交互期间统计 long task |
| `cdp-stress.js` | 快速缩放+平移压力测试 |

### 4.3 关键验证项

| 项 | 判据 |
|----|------|
| 主线程阻塞 | `longtask` 数量为 0，无 >250ms 卡顿 |
| 瓦片卡住 | `stuck === 0`（空白且非"无数据"标记） |
| 世界切换 | `worldKey` 变化且缓存清空 |
| 配色 | 用 `coverage.js` 统计彩色/绿色占比 |

### 4.4 像素覆盖率工具

`coverage.js` 纯 JS 解码 PNG（含全部 5 种 filter），输出：

用于对比修复前后的渲染质量。

## 5. 存档只读校验

红线：**绝不写入测试存档**。校验方式：

```powershell
# 1. 全项目搜索写操作，必须为 0
Get-ChildItem src -Recurse -Filter *.rs |
  Select-String -Pattern 'File::create|fs::write|OpenOptions|create_dir|remove_file|rename'

# 2. 检查存档文件修改时间
$s = 'C:\.minecraft\versions\GTNH 2.8.4\saves\新的世界 - 副本'
Get-ChildItem $s -Recurse -File |
  Where-Object { $_.LastWriteTime -gt (Get-Date).AddHours(-2) }
```

> **注意**：Minecraft 自身运行会写 `session.lock` / `level.dat` / `icon.png`。若发现写入，先比对时间戳与本次加载时间，不要急于判定是自己造成。

### 2026-09-15 更新
### 4.5 高度切层全黑（小数 zoom）的复现与验证

症状：大跨度切层（如全高→70）后预览瓦片偶发全黑，随便缩放一次恢复正常。

**复现关键**：必须先用滚轮制造小数 `mapZoom`。`zoomSnap: 0.25` 下滚轮会停在 `2.5`/`3.5`；仅用整数缩放（`setZoom(2)`）或纯滑块点击 40 轮均无法复现。`mapZoom=0.5` 是稳定复现点。

**验证脚本要点**（存临时目录，勿提交）：

- 探针必须同时看三个量，只看 canvas 像素会漏判：
  - `getImageData` 统计 alpha>0 像素（`dark = 100*(1-opaque/total)`）
  - `getComputedStyle(el).opacity`（瓦片可能已绘制但 opacity=0）
  - `Object.keys(L._tiles)` 的 zoom 段是否整数（`zs`），以及 `L._tileZoom`
- 触发：`Input.dispatchMouseEvent` 派发真实 `mouseWheel` 到地图中心制造小数缩放，再真实 `mousePressed/Released` 点击 `.slider input`。
- 断言：`post.dark < 40` 且 `zs` 全为整数。修复前 `mapZoom=0.5` 用例 `dark=100%`/`zs=["0.5"]`；修复后 `dark=23.1%`/`zs=["1"]`。

**URL 直连佐证**：Tauri 自定义协议 `tile.localhost` 不经过 CDP 的 Network 域（`Network.responseReceived` 抓不到），需在页面内 `fetch` 直接比对：

```
http://tile.localhost/<worldKey>/0/0.5/-3/-3.png?ymax=70  → Failed to fetch（小数 zoom）
http://tile.localhost/<worldKey>/0/1/-4/-3.png?ymax=70     → 200 image/png
```

**踩坑**：Tauri dev 模式窗口在测试脚本所在 shell 退出时会被连带杀掉，启动 app 与跑脚本必须在同一条命令内完成。
